# نکات امنیتی AMOS

## پیاده‌سازی‌شده
- **احراز هویت:** فقط کاربرانی که مدیر ساخته است؛ ثبت‌نام عمومی وجود ندارد. رمزها با bcrypt (Laravel) Hash می‌شوند. تغییر رمز اولیه در اولین ورود اجباری است.
- **محدودیت تلاش ورود:** پیش‌فرض ۵ تلاش ناموفق برای هر نام کاربری+IP در ۵ دقیقه (`LOGIN_MAX_ATTEMPTS`, `LOGIN_DECAY_SECONDS`) و Rate limit روی مسیر ورود. پیام خطا عمومی است (افشای وجود نام کاربری ندارد).
- **کاربر غیرفعال/تعلیق** نمی‌تواند وارد شود و اگر هنگام کار غیرفعال شود، در درخواست بعدی خارج می‌شود.
- **کنترل دسترسی در Backend** برای هر مسیر (Middleware `admin`) و هر رکورد (Policy) — جلوگیری از IDOR؛ قواعد مهم در لایه Service هم دوباره بررسی می‌شوند.
- **CSRF** روی همه فرم‌ها؛ **Escape خروجی** (Blade)؛ **ORM/Prepared Statements**؛ اعتبارسنجی سمت سرور.
- **Session امن:** HttpOnly، Secure (با HTTPS)، SameSite=Lax، رمزنگاری‌شده؛ بازتولید شناسه نشست پس از ورود.
- **هدرها:** `X-Frame-Options`، `X-Content-Type-Options`، `Referrer-Policy`، `Permissions-Policy`، HSTS روی HTTPS، `Cache-Control: no-store` برای صفحات واردشده.
- **آپلود:** ذخیره در `storage/app/private` (خارج از public)، نام تصادفی، فقط JPG/PNG/WEBP/PDF با بررسی پسوند و MIME واقعی، محدودیت حجم از تنظیمات، ارائه فقط از طریق کنترلر مجاز با هدر `nosniff` و CSP sandbox.
- **شماره حساب بانکی** با `APP_KEY` رمزنگاری و در UI ماسک می‌شود.
- **Audit Log** برای ورود/خروج، ایجاد/ویرایش کاربر، تغییر تنظیمات، همه تأییدها/ردها/برگشت‌ها، ایده‌ها و برداشت‌ها؛ شامل کاربر، رویداد، موجودیت، مقادیر قبل/بعد، زمان، IP و User-Agent. رمزها و داده حساس ثبت نمی‌شوند. رکوردها در سطح مدل غیرقابل ویرایش/حذف هستند و رابط کاربری فقط‌خواندنی است.
- **خطاها:** در Production (`APP_DEBUG=false`) Stack Trace نمایش داده نمی‌شود؛ صفحات خطای فارسی.
- **Installer** فقط قبل از نصب در دسترس است، دیتابیس دارای داده را بازنویسی نمی‌کند و پس از نصب قفل می‌شود.
- `.env` در Git و ZIP قرار نمی‌گیرد؛ `.htaccess` دسترسی به فایل‌های نقطه‌دار را مسدود می‌کند.

## چک‌لیست مدیر
- [ ] HTTPS فعال و `FORCE_HTTPS=true`.
- [ ] `APP_DEBUG=false` و `APP_ENV=production`.
- [ ] `/.env` از وب قابل دریافت نیست.
- [ ] پشتیبان منظم دیتابیس و پوشه `storage/app/private` و نگهداری امن `APP_KEY`.
- [ ] حداقل دو مدیر فعال برای جلوگیری از قفل شدن (سامانه اجازه غیرفعال کردن تنها مدیر را نمی‌دهد).
